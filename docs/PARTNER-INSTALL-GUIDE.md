# Partner install guide

This guide takes a reseller or partner from a blank machine to a running
Nventra POS at a restaurant. It covers the self-hosted Docker install that the
repository supports today. Commands assume a terminal on the host machine.

## 1. Hardware and network

- **Host:** one always-on machine on the restaurant's LAN (a small PC, mini PC
  or server). Any 64-bit Linux, macOS or Windows 10/11 machine that can run
  Docker works. Size the host for the number of tills and devices: it must run Docker
  and have enough free disk for the database and backups.
- **Network:** every till, tablet and KDS screen must reach the host on the
  same network. The app listens on **port 1995** by default
  (`HOST_PORT` in `.env` changes it). Give the host a fixed LAN IP or DHCP
  reservation so devices keep their address.
- **Internet:** not needed once running for order taking, billing, KDS and
  printing. It is needed for the first image build, for email (your SMTP
  server) and for any tunnel you choose.
- **Printers:** USB ESC/POS receipt printers and cash drawers are supported
  through USB passthrough, and network ESC/POS printers are supported by
  address. See section 6.

## 2. Install Docker

Skip any step whose check already works (`docker --version`,
`docker compose version`).

- **Linux (Debian, Ubuntu, Fedora and similar):**
  ```bash
  curl -fsSL https://get.docker.com | sudo sh && sudo usermod -aG docker $USER
  ```
  Log out and back in (or run `newgrp docker`).
- **macOS:** `brew install --cask docker`, then open Docker.app once so the
  engine starts.
- **Windows 10/11:** `winget install Docker.DockerDesktop`, reboot if asked,
  then launch Docker Desktop once. Run the install steps from **WSL2** or
  **Git Bash**, because the install script is a `.sh` file.

Docker Compose v2 must be available (`docker compose version`). Current Docker
Desktop and Docker Engine packages include it.

## 3. Install the application

From the repository root:

```bash
./install.sh
```

The script:

1. Checks that Docker, the Compose plugin and `curl` are present.
2. Creates `.env` with random `POSTGRES_PASSWORD`, `JWT_SECRET` and
   `UPDATER_TOKEN` values, only if `.env` does not exist. Re-running the script
   never overwrites `.env`. It only adds a random `UPDATER_TOKEN` to an older
   `.env` that has none.
3. Builds the images and starts the stack with `docker compose up -d --build`.
4. Waits for `http://localhost:1995/api/health`. Migrations run automatically
   when the backend container starts.

When it finishes, open **http://localhost:1995** and create the restaurant at
`/signup`.

To try the product with sample data first, run `./install.sh --demo` and sign
in with `owner@demo.local` / `Password123!`. Change that password or delete the
account before real use.

### Manual install

If you want to set your own secrets instead of generated ones:

```bash
cp .env.example .env          # set JWT_SECRET, POSTGRES_PASSWORD and UPDATER_TOKEN
docker compose up -d --build
```

Use `docker exec nventra-pos-backend npx ts-node prisma/seed.ts` only if you
want the demo data.

## 4. Configuration (`.env`)

| Variable | Purpose |
|---|---|
| `JWT_SECRET` | Signs login tokens. Required. Generated by `install.sh`. |
| `POSTGRES_PASSWORD` | Database password. Required. Generated by `install.sh`. |
| `UPDATER_TOKEN` | Shared secret between the backend and the `updater` container, which can control Docker. Required, at least 24 characters (`openssl rand -hex 32`). Generated by `install.sh`. |
| `HOST_PORT` | Host port for the web app. Default `1995`. |
| `FRONTEND_ORIGIN` | Public URL of the app, for example `http://localhost:1995`. |
| `COOKIE_SECURE` | Set to `true` only when the app is served over HTTPS (for example behind a tunnel). Leave `false` for a plain LAN `http://` install, or logins fail. |
| `SMTP_URL`, `SMTP_FROM` | Outgoing email. See section 5. Both empty means email is off. |
| `TRUST_PROXY` | Number of trusted proxy hops in front of the backend. Leave empty unless a reverse proxy is in front. |

Run `docker compose up -d` again after changing `.env`.

## 5. Email (SMTP)

Email covers receipts, reports and alerts. Set both `SMTP_URL` and `SMTP_FROM`
in `.env`, then restart the stack. Full details, including Gmail app
passwords and percent-encoding, are in [`docs/email.md`](email.md).

## 6. First login and printers

1. Sign in as the owner created at `/signup` (or the demo owner).
2. Go to **Settings** and set the restaurant and branch details, the tax regime
   and the UPI payee if UPI QR payments are used.
3. Create staff accounts and roles under the staff settings. Give each person
   only the permissions they need.
4. Add printers and test a receipt print. For USB printers, plug the printer
   into the host first. The backend container has `/dev/bus/usb` passed
   through. If a USB printer does not print, check `docker compose logs backend`
   for a printer-not-found error. For network printers, enter the printer's IP
   address.

## 7. Backups

- Data lives in two Docker volumes: `pg_data` (the Postgres database) and
  `uploads_data` (attachments and uploaded files).
- Schedule backups and run restores from **Settings → Backup**.
- Test a restore on a spare machine before the first live service.

## 8. Updates

- Re-run `git pull` followed by `./install.sh` to rebuild from the current
  source. The script never overwrites `.env` or existing data.
- The stack also includes an `updater` service. The in-app **Update now**
  button uses it to pull a newer published image. It answers only with
  `UPDATER_TOKEN`. Older installs had a public default here: re-running
  `./install.sh` replaces it with a random one. Without `install.sh`, add
  `UPDATER_TOKEN=$(openssl rand -hex 32)` to `.env` yourself.
- Take a backup before every update.

## 9. Stop, uninstall and remove data

- **Stop (keeps data):** `docker compose down`
- **Uninstall and delete all data:** `docker compose down -v`. This removes the
  database and uploads volumes and cannot be undone. Take a backup first.

## 10. Checklist before handover

- [ ] Host reachable from every till and tablet on port 1995
- [ ] Owner account created, demo account removed or password changed
- [ ] `.env` backed up somewhere safe (it holds the JWT and database secrets)
- [ ] Test order printed on each printer
- [ ] Test email sent (if SMTP is configured)
- [ ] One backup taken and one restore tested
- [ ] Support contact given to the restaurant, and [`SUPPORT-RUNBOOK.md`](./SUPPORT-RUNBOOK.md) shared with the support staff
