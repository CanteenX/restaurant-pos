# Client demo deployment (Vercel + Render + Neon, all free tiers)

This is a **demo instance only**, with sample data. It isn't how restaurants run Nventra POS; they self-host with Docker (see `install.sh`).

| Part | Host | Deploys when |
|---|---|---|
| Admin screens (`apps/web`) | Vercel (project on the `nventra01` account) | a merge to `master` |
| Backend API (`apps/backend`) | Render web service `nventra-pos-demo-api` (`render.yaml`) | a merge to `master` |
| Database | Neon Postgres, free tier, region Singapore | n/a |

The browser only talks to Vercel. `apps/web` proxies `/api/*` and `/socket.io/*` to `BACKEND_URL`, so login cookies stay first-party.

## 1. Database: Neon
1. Sign up at https://neon.tech and create a project. Choose Postgres 16 and region **AWS Asia Pacific (Singapore)**.
2. Copy the **direct** connection string, not the `-pooler` one, because Prisma migrations need it. It looks like `postgresql://USER:PASSWORD@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.

## 2. Backend: Render
1. Create the Blueprint from `render.yaml`, using the dashboard or the Render MCP.
2. When asked, set the following:
   - **`DATABASE_URL`**: the Neon string. Paste it in the Render dashboard, and never into chat or code.
   - **`CORS_ORIGIN`**: the Vercel admin URL, e.g. `https://<project>.vercel.app`.
   - `JWT_SECRET` and `UPDATER_TOKEN` are generated by Render.
3. The first deploy runs `prisma migrate deploy` automatically. When `https://nventra-pos-demo-api.onrender.com/api/health` returns OK, the backend is up.

## 3. Admin screens: Vercel
Use **Import** `CanteenX/restaurant-pos` with these settings:
- **Root Directory:** `apps/web`. Enable "Include files outside the root directory".
- **Framework:** Next.js. **Node:** 22.
- **Install command:** `cd ../.. && pnpm install --frozen-lockfile`.
- **Build command:** `cd ../.. && pnpm --filter @nventra/types build && pnpm --filter web build`.
- **Production branch:** `master`.
- **Environment variable:** `BACKEND_URL=https://nventra-pos-demo-api.onrender.com`, for Production and Preview. It's used at build time.
- **Environment variable:** `NEXT_PUBLIC_SOCKET_TRANSPORTS=polling`, for Production and Preview. Vercel proxies HTTP only and can't proxy WebSockets, so the browser must use long-polling (see Live updates under Free-tier limits).

## 4. Load the demo restaurant (once)
From a local checkout, with the Neon string in your own terminal only:
```bash
cd apps/backend
DATABASE_URL='<neon direct url>' npx prisma migrate deploy
DATABASE_URL='<neon direct url>' npx ts-node prisma/seed.ts   # prints the demo owner login
```

## Free-tier limits (fine for a demo)
- Render sleeps after about 15 minutes idle, so the first request then takes 30–60 s.
- Uploads (menu photos, logo) live in `/tmp` and vanish on restart or redeploy.
- No email unless `SMTP_URL`/`SMTP_FROM` are set. Local backups and the auto-updater are off.
- Live updates (kitchen display, order alerts) use socket.io long-polling through Vercel, which is slightly slower than WebSockets but works.
- Neon free: 0.5 GB storage, and the database auto-suspends when idle (a short wake-up).

## Render does not deploy when I push
- The service tracks the `master` branch only (see `render.yaml`). Merging to `staging` deploys nothing, on purpose. The release PR from `staging` into `master` is what deploys.
- If a push to `master` starts no deploy, open the service's **Deploys** tab. If it only shows the triggers **API** or **Blueprint sync** and never **New commit**, the Render GitHub app has no access to the private repo `CanteenX/restaurant-pos`. Fix it:
  1. In the Render dashboard, open **Account Settings**, then **GitHub**, and choose **Configure**.
  2. Grant access to the `CanteenX/restaurant-pos` repository. This needs a GitHub organisation owner.
  3. Use **Manual Deploy** once to confirm.
- Until that is done, start deploys by hand: in the dashboard, **Manual Deploy**, then **Deploy latest commit**. Or use the Render API or MCP trigger-deploy call. Nothing in the repo needs to change.
