# Translating the staff app (i18n)

The web app uses a small client-side i18n layer in `apps/web/lib/i18n/`, not
next-intl. The language is client state (saved in `localStorage`), so there
is no locale routing. Supported languages: English (`en`, source and
fallback), Hindi (`hi`), Spanish (`es`), French (`fr`).

## How it works
| File | Role |
|---|---|
| `locales.ts` | List of locales and their labels in the switcher |
| `dictionaries/<locale>.json` | Flat `key → string` maps; `en.json` is the source of truth |
| `translate.ts` | Pure lookup, fallback, interpolation and plurals (unit-tested) |
| `format.ts` | Number, currency and date formatting with `Intl` |
| `context.tsx` | `I18nProvider` and the `useI18n()` hook |
| `audit.ts`, `apps/web/scripts/i18n-audit.ts` | Find hardcoded strings |

```tsx
const { t, plural, formatCurrency, formatDate } = useI18n();
t("inventory.title");                       // typed: only keys in en.json compile
t("order.thankYouName", { name });          // "{name}" placeholders
plural("inventory.items", count);           // uses inventory.items.one / .other
formatCurrency(order.total);                // ₹1,50,000.00 in en/hi (lakh grouping)
```

- **Fallback:** a key missing from the active locale shows the English text.
  In development it also logs one `console.warn` per key. A key missing from
  `en.json` shows the key itself, and TypeScript rejects it at build time.
- **`<html lang>`** follows the chosen locale. Devanagari text uses
  Noto Sans Devanagari (loaded in `app/layout.tsx`, added to the font stack in
  `globals.css`).

## Key naming rules (for agents)
1. `area.thing` or `area.section.thing`, in camelCase, e.g.
   `inventory.lowStockOnly` or `inventory.po.receive`. The area is the
   `app/(dashboard)/<area>` folder name. `common.*` is for words used in 3 or
   more areas (Save, Cancel, Loading…). `nav.*` is for sidebar labels.
2. Name a key after its meaning, not its English wording. Do not reuse a key
   for a different context just because the English text is the same.
3. Plurals: `base.one` + `base.other` (add `.zero`/`.few` etc. only if a
   locale needs them). Use `{count}` in the string and call `plural(base, n)`.
4. Never build a sentence by joining pieces. Use one string with
   placeholders.
5. Money and dates always go through `formatCurrency` / `formatDate` /
   `formatNumber` from `useI18n()`, never `toFixed` or a hand-written `₹`.
6. Brand names, units (kg, ml) and data the user typed in are never
   translated.

## Adding strings (one area per PR)
1. Run `pnpm --filter ./apps/web i18n:audit <area>` to list the hardcoded
   strings in that area.
2. Add the keys to `en.json`, `es.json` and `fr.json`. The parity test
   (`dictionaries.test.ts`) requires all three to have the same keys.
   `hi.json` can be filled in later, but every key in it must also exist in
   `en.json`.
3. Replace the literals with `t()`, run `pnpm -r typecheck && pnpm -r test`,
   and run the audit again. The area's count should drop.

## Adding a language
Add the code to `LOCALES` and `LOCALE_LABELS` in `locales.ts`, its `Intl`
tag in `format.ts`, a dictionary file, and the import in `context.tsx`. The
kiosk only offers the languages in `components/kiosk/kiosk-header.tsx`
(`LOCALES_SHOWN`), so it has to be enabled there separately.
